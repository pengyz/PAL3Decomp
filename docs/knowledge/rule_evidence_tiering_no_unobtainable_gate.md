# 证据分级落盘规则：禁用「本质不可得」判据做硬拦截

**created**: 2026-10-21（4 轮 goal 停滞后第一性复盘定谳）

## 起因：9% 转化率的根因

4 轮 goal 落盘仅 5+5 条签名（占 1779 缺口的 0.6%）。
团队产出质量高（A 级证据 objdump 实录），但「四要素齐」门槛只放行 5/56 = **9%**。

## 二分定谳（用户质疑 → 数据回答）

**按「主张类型」分叉，不是按「工具能力」分叉**：

| 主张类型 | A 级可得？ | 证据源 |
|---|---|---|
| 参数个数 | ✅ 可得 | asm `retn N` |
| 成员偏移 | ✅ 可得 | objdump `0xNN(%reg)` |
| 调用点存在 | ✅ 可得 | objdump `call` |
| vtable 归属 | ✅ 可得 | objdump .rdata 槽 |
| 值位型 | ✅ 可得 | objdump `movl $0x41200000` = 10.0f |
| 成员尺寸 | ✅ 可得 | objdump `lea`+`call` 子对象 ctor |
| 参数类型（int/float/ptr）| 🟡 部分 | 值位型/访问形 opcode 时可，否则不可 |
| **参数语义名** | ❌ **本质不可** | 二进制**无名字** |
| **函数语义名** | ❌ **本质不可** | 二进制**无名字** |
| **返回语义** | ❌ **本质不可** | 寄存器宽度可得，语义不可 |

**原「四要素齐」门槛要求「调用点证据定参数类型」——那是本质不可得的**
⇒ 门槛错，不是证据不足。

## 规则（禁用不可得判据硬拦截）

### 1. 分档落盘（不是二元放行）

| 档 | 主张 | 证据要求 | 处置 |
|---|---|---|---|
| **A 档** | 结构性（参数个数/偏移/调用/vtable/值位型/尺寸）| **A 级**（objdump/retn）| 直接落盘 |
| **B 档** | 语义性（参数类型/语义名/返回语义）| **B 级**（decomp 消费证据）+ 标 `type_evidence:"B"` | 落盘 + 标注 |
| **C 档** | conf<60 | 证据不足 | 冻结 `_todo_`（禁伪语义命名）|

### 2. 验证用**编译消融**（金标准），不用证据完备度

```
落盘 N 条 → 跑 apply→export→codegen→probe → 记录错误数
   ↓
错误数降 = 真改善 ✓
错误数升 = 回退该批 ⚠️
```

**S2/总错误/门禁 是验证器**，不是证据完备度。

### 3. 二元放行禁用

「四要素齐」这类**全有或全无**的判据禁用 —— 因为它把「本质不可得」当必需。
改为**分级标注 + 编译消融裁定**。

## 历史教训（同族）

- **P0-3**：`proposed_signature` 批量套用致 S2 121→0（54 条批量）—— 但那是**批量**问题，不是**门槛**问题
- **reviewer REJECT（blocking 5）**：证据全线 B 级 ⇒ 立 A 级政策 —— 但政策**过严**，把本质不可得也要求 A 级
- **verifier 早说过**：「金标准应是**编译消融**」—— 未采纳，本轮采纳

## 核对出口

落盘记录必须含：
- `structural_evidence`（A 级：objdump/retn/值位型）
- `semantic_evidence`（B 级：decomp 消费）
- `confidence`（0-100，<60 冻结）
- `evidence_gaps`（明确写「哪些主张未达 A 级」）

## 与 CLAUDE.md 的关系

- **不违反**「每一处 annotation 修改必须有二进制直接证据」—— 结构性主张仍须 A 级
- **细化**「禁止猜测性修改」—— 语义性主张用 B 级**不等于猜测**（有 decomp 消费证据）
- **新增**「验证用编译消融」—— 与「字节匹配是第一优先级」一致
