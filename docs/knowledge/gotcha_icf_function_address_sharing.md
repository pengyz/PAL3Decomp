**现象**：用"函数在 vtable 里的出现位置"判定类归属时，遇到一个 25 字节函数
`0x43D920` **同时**是两张互不相关表的 slot3：

- `0x56AD08`（表 `0x56ACFC`，一个 84 字节 UIWnd 派生类的表）
- `0x56AFBC`（表 `0x56AFB0`，**`UIWnd.json` 自己声明**的一张表，由多继承类 ctor `0x44A790` 安装）

第一反应是"其中一处归属错了"。**不是。**

**为什么**：`cmake/MSVCSettings.cmake:141` 就是 **`/OPT:ICF`（合并相同的函数/数据）**。
链接器把**机器码完全相同**的函数折叠成一个地址，于是多张 vtable 可以合法地指向同一个函数
（多态类的 `??_G`/`??1`/极简 `Destroy` 最容易同形）。因此：

- "**同一函数出现在两张不相关的表 ⇒ 矛盾**"是**无效推理**；
- 反过来，"**某函数只被一张表引用 ⇒ 它属于那张表的类**"也不成立（它可能被 ICF 折叠后
  另一份副本被别处引用，而引用在折叠后都指向同一地址）。

**如何绕过**：
1. **不要**用"函数地址唯一性"做归属 A 级证据。要用**语义 + 数据流**：
   本次决定性判据是 **`[this+76]` 的语义** —— `0x43D920` 把 `[this+76]` 当**指针**解引用并置 0，
   而候选类 `UIStatic` 的 ctor（`0x440740`）在执行 `440779 movl $0x1,0x4c(%esi)` 时把 `[this+76]`
   写成**整数 1**；若 `0x43D920` 是 UIStatic 的方法，就会把地址 1 当指针解引用 ⇒ **不可能**。
2. 需要唯一归属时，**两张表各自都要有一个 slot3 实现**（即承认 ICF 共享，给另一张表的所有者也补记录）。
3. 判"函数 X 属于类 C"时优先用：**被 C 的已知方法以 `this` 调用**（本次 `0x43DAB0` 被
   `0x43D940`(Render) 以 `mov %esi,%ecx` 调用 5 次）、**参数/返回值语义**、**成员偏移的数据流**。

**何时使用**：任何"该函数挂在两张表里"、"这个函数到底属谁"、"某地址被多个类引用"的判定；
写取证工具时遇到**同一 VA 出现在多个容器**，先查是否 ICF，再谈矛盾。
