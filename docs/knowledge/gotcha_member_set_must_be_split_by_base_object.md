# gotcha：判归属时成员集合必须**按基对象分离**

## 现象（2026-09-22 实测）

用"函数内 `[this+off]` 的成员集合 ⊆ 某类的成员表"判归属（本仓规"禁止仅凭 signature 的 this 修正归属，
必须有成员访问证据"的机械化），试点 `audit_attribution.py` 得到：

```
SceneMgr::Create@0x004CDA10   现归 SceneMgr   unique ⇒ 归属可证（唯一相容 CEffMgr）   ← 明显错 ✗
```

**根因**：`Create` 提取到的偏移含 `0xA91C / 0xA920 / 0xA924 / 0xA928 / 0xA92C …`，
而 `CEffMgr` 的尺寸是 **0xA930** ⇒ 这些是**`CEffMgr` 的字段**（函数里创建特效时访问了特效管理器）✗
⇒ naive 的"`mov R, ecx ⇒ R ≡ this`"追踪把**经其它指针/全局访问的字段**也算进 this 的成员集合 ✗✗
⇒ 于是"唯一相容 CEffMgr"这个结论**在数据上自洽，但问题问错了** ✗

## 正确做法

1. 访问集合必须**按基对象分离**：每个 `[R+disp]` 要判定 `R` 的**来源**是 this，还是"从全局/其它指针加载"✗
   （需要**寄存器级 def-use/provenance**，不能只看"是否曾由 ecx 赋值"）
2. 分离后，只有**属于该对象**的偏移集合才用于判归属 ✓
3. 辅证仍需要：vtable 槽位指向该函数 · ctor/dtor 的 vptr 存储 · 调用点类型 ✓

## 教训（与 TDD 的关系）

* **判据**（唯一相容性四态 + 尺寸边界 + 匹配率/领先幅度）可以用纯函数**测试驱动**并做到可靠 ✓（本工具 20/20 ✓）
* 但**证据提取器**的正确性**不能在纯函数层证明** ✗ —— 必须用**真实函数**做端到端试点，
  并警惕"结论自洽但问题问错"的情形 ✓
* ⇒ 工具必须显式标注**实验性状态**，不得用于改归属（本工具已加）✓

## **何时使用**
* 任何"用访问集合判归属/判类型"的工具：先问"这些偏移**真的都属于同一个基对象**吗？" ✗
* 看到"唯一相容某个**意外**的类"（尺寸相近、语义无关）⇒ 优先怀疑**基对象混淆** ✓
