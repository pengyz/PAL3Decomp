# decision：以二进制为唯一 SoT 的闭环推断

**问题**：假设**没有任何标注**，如何从零逐步明确一个类型的内存布局与类型？
**答案**：布局**不是被存储的**，而是**从指令的寻址方式里推断出来的**。所以流程必须是
「机械提取二进制可观测量 → 形成假设 → 用二进制可否证 → 只把 CONFIRMED 写回」。

## 0. 两种裁判抓的是**不同类别**的错误（2026-09-21 实测，必须并存）

| 裁判 | 观测量 | 抓什么 | 抓不到什么 |
|---|---|---|---|
| **二进制裁判** | 真实指令里的 `[reg+disp]` | **注解偏移/类型/归属** 与二进制**不符** | 发射层错误（注解与二进制一致、但生成头编错）✗ |
| **编译器裁判** | `offsetof(生成头里的类, 成员)` | **发射/布局**漂移 | 注解本身错（它会与错注解"一致地错"）✗ |

**实证**：`SceneMgr::ClearInactiveRoles` 的**二进制**是 `mov ecx,[eax+0E0E0h]` ⇒
二进制与注解**都是 0xE0E0**（注解对 ✓），而**生成头编出来是 0xE0BC** ✗
⇒ 这个 bug **只有编译器裁判能抓**；反过来，注解偏移写错时**只有二进制裁判能抓** ✓

## 1. 六个关注点的可观测量 / 能证明 / 不能证明

| 关注点 | 二进制可观测量 | **能**证明 | **不能**证明（须标为未验证/推断）|
|---|---|---|---|
| **字段偏移** | 该寄存器已证明是 `this` 时的 `[reg+disp]` | 该偏移**存在**字段（宽度由指令给出）| 未访问的字段（**未观测 ≠ 不存在**）|
| **字段宽度/类型** | 访问宽度（BYTE/WORD/DWORD/QWORD · `fld dword/qword` · XMM）；运算（`fdiv`⇒float、`imul`⇒整型、`cmp`+`jl`/`jb`⇒有符号/无符号）；`.data/.rdata` 里初始化字面量的宽度与值 | 宽度 + int/float/指针性 + 有/无符号 | 精确源码类型名（`int` vs `long` vs enum）、struct vs class |
| **字段名** | ①PDB（**PAL3A ≠ PAL3**，仅参考）②RTTI `??_R*` ③字符串/诊断信息 ④mangled 符号 | **仅当**上述来源存在时才是**证据** | 绝大多数情况：名字**无从由二进制证明** ⇒ 只能是**标签**，必须标证据等级，**不得当事实** |
| **成员函数归属** | `__thiscall` + ECX=this 的 def-use；函数体内 `[this+disp]` 的**成员偏移集合**是否**只与某个类相容**；vtable 槽位指向它；ctor/dtor 里的 vptr 初始化 | 当成员集合与其它类**不相容**时：该函数**只能**属于该类 ✓ | 多个类布局相同/访问集合重叠时 ⇒ 归属**不唯一**（需更多证据）|
| **对象尺寸** | `operator new`/`malloc` 的立即数；数组步长（`imul`/`shl` + `lea`）；相邻全局间距；`memset`/`memcpy` 长度 | 尺寸（多为上/下界，需**交叉**取交）| 精确末尾填充 |
| **虚表** | `.rdata` 里的函数指针数组；ctor 里的 vptr 存储；槽位调用点 | 槽位**数量与顺序**（= 声明顺序）✓ | 各槽位的**参数类型**（需签名证据）|

## 2. 闭环（每一步都可机械执行、可复核）

```
对每个候选实体（对象 / 字段 / 函数 / 虚表）：
  H ← 当前假设（来自注解 / PDB / 名字 / 反编译文本）
  E ← 机械提取的二进制证据（带 VA + 指令做证据指针）
  判定：
    CONTRADICTED  ⇒ **报警，人工裁定**（不得自动改）✓
    CONFIRMED     ⇒ 允许写回，**必须带证据指针**（VA:指令）
    NO-EVIDENCE   ⇒ 保持"未验证"状态，**不得当成事实**（未观测 ≠ 不存在）
```
三条纪律（与既有证据分级一致）：**未观测 ≠ 不存在** · **名字 ≠ 证据** · **多来源冲突时以二进制为准**。

## 3. 实现形态：`tools/infer_layout_from_binary.py`（**DAG 序**）
1. **对象识别**：类的各方法入口 ⇒ `__thiscall` 的 `ECX = this`；
   并对"把 this 缓存进 callee-saved 寄存器"做**寄存器来源追踪**（把 `mov esi,ecx ⇒ _ESI ≡ this` 机械化）✓
2. **字段观测**：在方法范围内提取 `[reg+disp]`（含宽度/助记符）⇒ `offset → {(width, kind, count)}`
   —— MCP `insn_query` 已实测可用（`{start,end}` 作用域）✓
3. **尺寸观测**：`new`/`malloc` 立即数 · 数组步长 · 相邻全局间距 · `memset/memcpy` 长度
4. **虚表观测**：`.rdata` 指针数组 + ctor vptr 存储 + 槽位调用点
5. **比对**：与 annotation 的 offset/type/name/归属逐项 ⇒ CONFIRMED / CONTRADICTED / NO-EVIDENCE
6. **DAG 序**：**基础类型先**（其尺寸确定后才能判复合类型的字段边界与剩余空隙）
7. **输出**：冲突清单（报警）+ 证据指针 ⇒ **人工介入**（不自动修）

## **何时使用**
* 任何"这个偏移/类型/归属对不对"的问题：**先问二进制能证明到哪一步**，再决定证据等级；
* 建任何布局/类型/归属校验器时：**同时要有二进制裁判与编译器裁判**（二者互补，见 §0）；
* 想"自动修"时：**停在报警**（使用者 2026-09-21 明确要求人工介入）。
