# 深度复核跑得久是常态——禁止因等待中断，判"技术失败"须凭实证

事实：本仓深度对抗复核（8 问级实现/裁定复核）实测常态 **7-8 轮**才出完整结报
（ff86c62f/c34f38aa/84fd2ef7/21984786 均如此）；编排侧曾因 4-6 轮无输出就判
"技术失败"强制中断 3 个复核（b827549e/75e5af3b/fcce0c24），被用户纠正：
**"你为什么强制停止子 agent，让它跑完"**。

**为什么：** 等待 ≠ 失败。复核员在做大量只读探针/独立复算时输出沉默是正常工作态；
中断会毁掉其积累的证据链，还会造成"独立确认层缺失"的自伤（补偿性自核永远替代不了
独立复核）。真正的技术失败应凭实证：崩溃退出/报错栈/明确的不可恢复状态——
"还在跑"永远不是中断理由。

**何时使用：** 编排侧等复核结报时——(a) 只发**一次**收敛引导（且措辞是"优先交付某几问"，
不是"必须现在交"）；(b) 此后耐心等，期间做不冲突的并行工作；(c) 判失败前必须有崩溃/
停滞实证；(d) 若确需中断（如用户指令），中断后可用 send_message **恢复**让其跑完
（被停的 agent 保留上下文可续）。
