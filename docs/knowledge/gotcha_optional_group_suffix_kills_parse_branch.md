**现象**：`tools/sig_evidence.py` 从 IDA 反汇编里取函数尾 `retn` 立即数、换算成
`__thiscall` 的栈参数个数（`slots = N/4`），供 `ast_transform` 的"显式 this 证据门"
判定静态调用能否转成员调用。这个门决定了**全仓**的生成文本，可它读到的"真值"是错的。

**根因（一行）**：
```python
RET_RE = re.compile(r'^(?:retn|ret)(?:\s+([0-9A-Fa-f]+)h?)?\s*$')  # h? 在捕获组外
def parse_ret_num(rest):
    if rest.lower().endswith('h'):      # ← 对这条正则永远是死代码
        return int(rest[:-1], 16)
    return int(rest)
```
`h?` 被写在**捕获组之外**，于是 `retn 20h` 只捕获到 `'20'`、`h` 被吃掉，
`parse_ret_num` 那个**专门为 h 后缀写的**分支再也进不去 ⇒ 所有多位立即数按**十进制**解析。

**实测（直接调用这两个函数）**：`20h`→20（真值 32）、`10h`→10（16）、`14h`→14（20）、
`0Ch`→`int('0C')` **ValueError**；单值 `0..9` 两种读法相同、无影响。

**A 级依据（文本形态）**：`original/PAL3.exe.asm` 里**所有**多位立即数都带 `h`
（`10h` 199 处、`14h` 151、`18h` 122、`20h` 17、`0Ch` 916、`1Ch` 11、`44h` 5），
且"无 `h` 的多位数"命中 **0** 条 ⇒ 凡 `rets` 里 ≥10 的值，源文本必然是某个 `NNh`。
这条统计把"误解析"从推断升级为**可判定**。

**三种后果（都静默）**：
| 形态 | 解析值 | 后果 |
|---|---|---|
| `10h`/`14h`/`18h`/`44h` | 非 4 的倍数 | grade `B-ODDRET` ⇒ **不发 `slots`** ⇒ 证据门**永久阻塞**（假阴性） |
| `20h`/`28h` | ≥10 且是 4 的倍数 | **通过 %4 校验** ⇒ 发布**错 slots**（5 而非 8）⇒ 门判错 |
| `0Ch`/`1Ch` | `int('0C')` | **ValueError**，被 `rets_of` 的 `except Exception` 吞成 `C-DISASM-ERR` ⇒ 同样阻塞 |

**"现场"其实一直留在产物里**：`_sig_evidence_pack.json` 的 `err` 字段写着
`invalid literal for int() with base 10: '0C'`（**9 条**），只是**没有任何下游消费它**。
`B-ODDRET` 17 条、`rets` 非 4 倍数的 17 条 —— 这些自证信号都在，但没人看。

**修法**：把 `h` 收进捕获组（`([0-9A-Fa-f]+h?)`），让 `parse_ret_num` 原有的分支复活。
**修的范围必须收窄**：只动**可被证明**解析错的条目（`B-ODDRET` ∪ `C-DISASM-ERR` ∪
`rets` 里存在 ≥10 且为 4 倍数的值，共 29 条）。实测若"顺手重新评分整张 pack"，
会误伤 **54 条 `A-V2`** —— 那是现行评分函数**产不出**的更高等级（pack 由别的版本写入），
重评会把它们降级。**"顺手重算"是把工具口径差异当成了修复。**

**结果**：`B-ODDRET` 17→0、`C-DISASM-ERR` 9→0；26 条新发布 `slots`、3 条 slots 被修正
（5→8、7→10、5→8）；错误普查里**只有 `C2660 −2`**、零新增错误、零净增错误码，
`TextureLib.cpp` 转 ok（S2 64→65），L1 按多重集恒等。

**可复用的教训**：
1. **可选后缀要放进捕获组**，否则"为它写的下游分支"永远不会执行——这类死代码
   用覆盖率看不出来（分支存在、只是恒不可达）。
2. **产物里已经写了失败现场（`err`）却没人消费**，等价于没有记录。证据链的末端
   要有消费者。
3. 修"证据源"时必须区分「被证明错的」与「口径不同的」，前者可改、后者一改就误伤。
