# L1 上行≠字节收益——语料增长混淆与正确字节面证据

事实：match 的 L1（字节全同函数数）跨时点比较会被**语料总体变化**混淆：本仓实测
L1 63→68 的 +5 全是新转绿单元的符号进语料（CCBMagicWindow/UIProgressBar），字节面
贡献为 0——真正的字节证据是 `s4_baseline` 共享行 diff（与 HEAD 记录共享 323 行，
status/match_pct/size **0/323 变化**）。

**为什么：** L1 是绝对计数（分子），可比总体（分母）随文件集/转绿单元漂移；棘轮提示
"population 已变化 ⇒ 不可直接比较"就是这个机制。本仓曾因陈旧棘轮造成多轮"假回归"
归因成本（03:40 基线 3 天陈旧，每轮 codegen 都要重新归因同一批真新增）。
另注意：L1 棘轮**回写基线**——事后查文件判断退化无效，必须同运行读输出（CLAUDE.md 既有规）。

**何时使用：** 任何"字节面零回退/收益"主张——用 (a) 受影响 TU 逐函数 match diff=0
（同运行读）或 (b) 共享行 diff（0/N 变化）作证；禁止用 L1 增减直接归因工项收益。
工项收尾时点（W 边界）显式 `match --rebaseline "<理由>"` 归档，避免下一轮归因混淆。
