# decomp 调用图重建必须用显示名——MSVC 修饰形匹配会漏光

事实：从 asm/pal3/decomp/*.json 重建调用图时，用 JSON `name` 字段（MSVC 修饰形
`?M@C@@QAEXXZ`）做被调者匹配，召回率塌到 **9.2%**；改用 `decompiled_c` **显示名**
（`Cls::Method` 形）后召回复原 **81.3%**（155c71bb 复核实测：调用图邻域判据精确 92.5%）。

**为什么：** decomp 正文渲染的是显示名（Hex-Rays 解码后形态），而 `name` 是 IDA 原始
修饰符号——两者字面永不匹配。同族坑：按文件名/字形正则分桶（`^Cls_` 等）也会失真
（completeness_census 初版 3,304"类方法"虚高 470=14.2%——纯字形 ≠ 语义）。

**何时使用：** 凡做函数分类/调用图/覆盖分析——名字匹配一律以 `decompiled_c` 首行/正文
显示名为准（thiscall+`Cls::` 形=类方法、`scalar deleting destructor` 等=合成体确定性判据）；
`name` 字段仅作地址键用。判据组合（155c71bb Q5 选型）：合成体确定性前置剔除 → 命名形初筛
（精确 97.1%/召回 83.8%）→ 调用图收敛（92.5%/81.3%，显示名建图！）→ 人工裁冲突；
FLIRT 只作旁证（本仓 PAL3 侧无签名库，覆盖 13.5%）。
