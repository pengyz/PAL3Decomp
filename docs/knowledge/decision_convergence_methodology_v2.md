## 附2：判据 v2 再修正（T9 揭示，2026-10-12）

**T9 实测**：S2 101→106（+5）· 总错误 1720→1643（−77）· **L1 86→94（+8）**。

**⚠️ 但 L1 率 86/459=18.7% → 94/568=16.5%（下降）** —— 因**分母随可比池扩大而变大**（520/613→568/669）。

**⇒ 「L1 率」作为指标有问题**：
| | |
|---|---|
| 分母 = L1 + partial | 随可比池扩大而变大 |
| ⇒ 率下降即使 L1 增长 | **指标与目标脱钩** |

**⇒ 判据 v2.1**：
| 指标 | 用途 |
|---|---|
| **L1 绝对数** | ✅ **主判据**（86→94 是实质进展）|
| **L1 / 总函数数**（3649）| ✅ 辅助（覆盖率）|
| ~~L1 / (L1+partial)~~ | ⚠️ **降级**（分母不稳，参考用）|

**⇒ 「L1 率离开 18-19.5% 平台」的目标表述需修正** —— 改为「**L1 绝对数持续增长**」。

## 附4：verify 命令的可靠性（T9 揭示 captain 的错）
`grep -c 'int (CEffect::*)' CEffect.h` 是 **BRE 死模式** —— 对合法 C++ 拼写 `int (CEffect::*)(int)` 亦 0 命中。
**⇒ 真证据**：`grep -F 'int (CEffect::**)(int)'` 在单元取证（CEffCylinder×2/CEffAction×2/CEffect×6）。
**⇒ 教训**：verify 命令本身要**先自测**（用已知正例验它能命中），否则「verify 通过」是假绿。
