已建立持续验证工作流程！现在的工作方式是：

┌─────────────────────────────────────────────────────────────┐
│  每次迭代（15-30分钟）：                                    │
│                                                             │
│  1. 选择 1-3 个函数                                         │
│  2. 添加到源文件                                            │
│  3. python verify_build.py  ← 验证编译                     │
│  4. git commit              ← 提交                         │
│  5. 重复                                                    │
└─────────────────────────────────────────────────────────────┘

═══════════════════════════════════════════════════════════════
第一步：验证当前状态
═══════════════════════════════════════════════════════════════

立即执行（确认基础可用）：

  > python verify_build.py

如果通过 → 说明工具链正常，可以开始工作
如果失败 → 运行 python check_toolchain.py 检查环境


═══════════════════════════════════════════════════════════════
第二步：提交基础状态
═══════════════════════════════════════════════════════════════

  > git add -A
  > git commit -m "Setup complete: incremental workflow established"


═══════════════════════════════════════════════════════════════
第三步：选择工作方向
═══════════════════════════════════════════════════════════════

方向 A：完善 topo.dll（如需二进制匹配）
  - 剩余 ~314 个函数
  - 需要 VC6 SP6
  - 可以验证字节级匹配

方向 B：启动 gbengine.dll（快速推进）
  - 3,213 个函数
  - 从简单的开始
  - 建立模块框架


═══════════════════════════════════════════════════════════════
核心原则
═══════════════════════════════════════════════════════════════

  ✅ 永远保持代码可编译
  ✅ 小步迭代，频繁验证
  ✅ 每个工作单元都提交
  ✅ 遇到错误立即修复

  ❌ 不要堆积大量未验证的代码
  ❌ 不要长时间不提交
  ❌ 不要跳过编译步骤
