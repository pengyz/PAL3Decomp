## 1. 级联机理定谳

## 2. 真身定谳

### 2.1 `_scalar_dtor_DD70` @ 0x0047DD70 = **B 组真 scalar deleting dtor（??_G），30B 教科书形**

objdump（今日，original/PAL3.exe）逐字节：

```
47dd70: push esi / mov esi,ecx        ; esi = this
47dd73: call 0x47dd90                 ; ← 纯析构 ~UITitle_YXXX（SEH 包装体；体内 lea 0x48(%esi) + 写双 vptr 0x56B8A4/0x56B898）
47dd78: testb $0x1, 0x8(%esp)         ; test flags,1
47dd7d: je  0x47dd88
47dd7f: push esi / call 0x541d10      ; operator delete(this)（0x541D10=delete，同研究 #16 xref）
47dd88: mov eax,esi / pop esi
47dd8b: ret 0x4                       ; __thiscall，栈 1 参=flags
```

- 形态 = 「call 纯析构 → test flags,1 → delete → return this」**30B**（0x47DD70..0x47DD8D，尾 NOP）——与背景约束「scalar deleting dtor=教科书 30B 禁手写」逐字吻合。
- **地址后缀解析**：`DD70` = **0x0047DD70**（注解键、decomp JSON address、objdump 三方一致）。简报猜测的 0x43DD70 **不成立**（0x43D8xx 是 UI3DCtrl `_scalar_dtor_D860` 族，另一条）。
- 真名应为 `??_GUITitle_YXXX@@UAEPAXI@Z`；现名 `_scalar_dtor_DD70` 是管线地址后缀占位（research_dtor_identity §0「命名不可信」）。
- **处置归属**：B 组 ⇒ 源写 `~UITitle_YXXX()+delete`，MSVC6 COMDAT 再生；**禁手写（LNK2005）**；调用点不应按名调（应是 delete/析构语义形）。

### 2.2 0x47E570 = D 组 adjustor thunk（字节形实锤）

`83 e9 48 / e9 f8 f7 ff ff` = `sub ecx, 0x48; jmp 0x47DD70` —— 第二 vptr 在 this+0x48（ctor 体 0x47DD90 内 `lea 0x48(%esi),%edi; mov [edi],0x56B898` 实证），MI this-调整后转发删除析构。L417 的 `((UITitle_YXXX*)((char*)this-72))` 即该调整的 Hex-Rays 表象。

### 2.3 UITitle_YXXX.json 中 `_scalar_dtor_DD70` 的形态（简报问「在 methods 还是别处」）

**两处都在**：
- `methods["0x0047DD70"]`：name `_scalar_dtor_DD70`、signature `int __thiscall(void *Block, char)`、**ordinal 5、evidence_level A**、source=五面卡（删析构 133 正名 2026-10-17）；
- `vtables[0](0x56B8A4).slots[5]` 与 `vtables[1](0x56B898).slots[8]` 均含 `0x0047DD70`（from:null）。

⇒ 它不是「误挂的字符串残留」，是**证据齐全的注册条目**——问题在发射政策（B 组不发射）与名形闸的矛盾，不在这条注解本身。
