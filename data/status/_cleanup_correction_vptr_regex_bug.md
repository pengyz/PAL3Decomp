# 更正：所谓"vtable 地址有两个互不相交的数据源"**是我的正则 bug**（captain 自纠）

> 本文件**推翻** `_cleanup_finding_vtable_addr_sources.md`（同目录）。
> 该文件的结论"注解 92% 的 vtable 地址不在 ctor 实写集合里 ⇒ 两批数据源互不相交"
> **完全是我的测量 bug 造成的**。

## 1. 真实情况（修 bug 后实测）

```
                       修前（坏正则）   修后（正确形态）
ctor 实写地址（去重）        467    →     381
匹配行数                    476    →     718
注解地址 ∩ ctor 集合         **7**  →     **91 / 93**
0x56A600 在集合里            False  →     **True**
```

**⇒ 注解记录的 93 个 vtable 地址里有 91 个确实是"ctor 实写的表"（98%）。**
**⇒ 两批数据源高度一致，"互不相交"纯属我的测量错误。**

## 2. bug 的精确原因（`tools/vtable_compare.py` 的 `_VPTR_WRITE`）

`objdump` 对指令字节做**列对齐**，不同长度指令的空格数不同：

```
6 字节:  401007:\tc7 06 00 a6 56 00    \tmovl   $0x56a600,(%esi)      ← 无位移
7 字节:  4c056b:\tc7 45 00 e4 f5 56 00 \tmovl   $0x56f5e4,0x0(%ebp)   ← 有位移
```

**我在同一个正则上连错 4 次，逐条留痕**：

| 版本 | 写法 | 后果 |
|---|---|---|
| ① | `(?:[0-9a-f]{2} )+`（每字节后必须空格）| 只命中"字节数为奇"的行；**无位移形态全丢** |
| ② | `(?:[0-9a-f]{2}\s+)+` | 字节组**尾部**的 `\s+` 把 `movl` 前的空隙吃掉；两个量词**不能共享同一段空白** ⇒ 匹配失败 |
| ③ | `(?:[0-9a-f]{2}\s+)+\s*movl?` | ② 的问题仍在（多放的 `\s*` 救不了）|
| ④ | 位移写成 `(?:0x0\()?` | 要求**字面量 `0x0`** ⇒ 无位移形态 `(%reg)` 全丢 |
| ✅ | **`(?:\s*[0-9a-f]{2})+\s+movl?`** 且位移 `(?:0x[0-9a-f]+)?\(%[a-z]+\)` | **正确**：`\s*` 在**每字节之前**，最后一段空隙留给 `\s+movl?` |

**验证方式**：先用**文件真实行**做断言（6/6 命中、718 行匹配），再写进文件。
**教训**：测试用例里的 `'\t'` 是**字面反斜杠-t**，会掩盖真实的制表符问题 ⇒ **必须用真实行**。
